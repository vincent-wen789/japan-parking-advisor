# Japan Parking Advisor（日本停车助手）

一个在**日本**开车用的停车决策助手——地域性极强、专为日本设计，不是世界通用解法。给它一个目的地，它联网现搜、按**你的车**筛选，返回一个首选 + 2-3 个并列就近备选——每条都配一个 Google Maps 链接。

> 🌏 English: [README.md](README.md) ・ 日本語: [README.ja.md](README.ja.md)

## 为什么有这个工具

Google Maps 能告诉你哪里有停车场，但它不会告诉你：
- **我的车开得进去吗？** 限高、機械式车库的陷阱（限高 1.5m 的立体塔库会把大多数 SUV 挡在外面；有些库只有自走层能停）。
- **对**我这趟**到底哪个最便宜？** 时间料金 vs 最大料金 vs 提携割引。
- **开过去发现满了怎么办？**——最高频的真实失败。所以这个工具永远给**并列备选**，而不是只给一个答案。

范围：**专门针对日本**（数据源、搜索词、车库类型如 自走式/機械式、割引规则都是日本的）。停车是地域性极强的问题——这不是一个放之四海皆准的工具。底层机制理论上可改指向别国，但现状假设的就是日本，日本以外不支持。

## 两个层级 —— 该用哪个

| 层级 | 是什么 | 链接质量 | 需要 | 什么时候用 |
|---|---|---|---|---|
| **L1 — skill**（`skill/`） | 完整的 agent skill | **WYSIWYG 车库名片链接**（*仅在有 headless 浏览器栈时*）；否则优雅降级 + 明确说明 | 一个联网搜索 API + 一个 headless 浏览器（见 `skill/SETUP.md`）；为 Claude Code 这类 agent 设计 | 你跑 agent、想要最好的已核验链接 |
| **L2 — prompt**（`prompt/`） | 一段复制粘贴的 prompt | 普通 Maps 链接——**无法核实链接指向的就是那个对的车库**（防同名连锁 / 租车店的消歧只有 L1 有） | 任何带联网搜索的 LLM | 你只想要个快答案、零配置 |

**没在跑 agent 的人，大多数该用 L2。** 它做同样的搜索 + 车筛 + 诚实推理；你只需开车前点开每个链接确认是不是目标车库。

### 设计（一套引擎，两层壳）
L1 和 L2 共用一套引擎——同样的数据/过滤/呈现模型、同样的诚实规则、同样的排序。只有运行环境不同（带浏览器的 agent → 满血；聊天 LLM → 降级）。两层都必须满足的共同规则写在 [`skill/ENGINE-INVARIANTS.md`](skill/ENGINE-INVARIANTS.md)。

## 安装

**L1（skill）**：把 `skill/` 目录拷进你 agent 的 skills 文件夹，然后按 [`skill/SETUP.md`](skill/SETUP.md) 配三个依赖（搜索 API / headless 浏览器 / 抓取器）。没有 headless 浏览器它也能跑——链接降级成普通 Maps + 一句提示。

**L2（prompt）**：打开 [`prompt/PROMPT.zh.md`](prompt/PROMPT.zh.md)（或 [`.md` 英文](prompt/PROMPT.md) / [`.ja` 日文](prompt/PROMPT.ja.md)），复制分割线以下的全部，粘进任何带联网搜索的 LLM，然后告诉它你要去哪、你的车高多少。

## 数据诚实怎么处理

异常触发：它**不会**逐条报来源/日期/可信度（那是噪音）。只在某条**真有问题**时才出声。**唯一的硬规则**：限高/限幅未确认必须**当场说**——"我的车能不能进"是安全问题不是噪音——而且这种车库绝不当首选。

## 关于速度（冷启动）

这个开源版是**联网搜索优先**——它带一个小的示范数据集，**不是**预建的区域缓存。所以第一次查一个新地方会比私有缓存版慢一些、确定性低一些。你可以随时间自己攒本地缓存（示范数据集的格式见 `skill/references/parking-data.md`）。

## 御三家 LLM 的已知差异

三家大 LLM 在 L2 prompt 上行为不同（联网搜索默认值、链接格式）。不承诺等价——见 [`KNOWN-DIFFERENCES.md`](KNOWN-DIFFERENCES.md)。
